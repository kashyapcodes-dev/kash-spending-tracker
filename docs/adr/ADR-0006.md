# ADR-0006: M0 Tooling Choices

## Decision

For the kash spending tracker (M0), we chose:

- **Package Manager**: pnpm
- **Monorepo Tooling**: Turborepo
- **Web Framework**: Next.js 15 (App Router)
- **Test Runner**: Vitest
- **TypeScript**: Enabled everywhere
- **Linting**: ESLint (flat config) + Prettier
- **Formatting**: Prettier
- **UI**: shadcn/ui (Tailwind-based components)
- **Testing**: Playwright (E2E) + Vitest (unit/integration)

## Context

### Problem Statement

We needed a scalable monorepo setup for a new web application that would:
1. Support multiple packages and apps in one repo
2. Enable shared configuration across packages
3. Provide fast development experience
4. Support automated testing and CI/CD

### Options Considered

1. **pnpm + Turborepo** (chosen)
   - Fast installs via hardlinks
   - Built-in caching for builds
   - Excellent monorepo support
   - Works well with Next.js

2. **npm + lerna**
   - Mature but slower
   - More complex setup
   - Less caching optimization

3. **yarn workspaces + workspace**
   - Good performance
   - Less documentation for advanced features

4. **Nx**
   - Powerful but heavier
   - More opinionated
   - Steeper learning curve

## Consequences

### Positive
- Fast development workflow with Turborepo caching
- Consistent TypeScript configuration across packages
- Easy to add new packages/apps
- Strong community support for chosen tools

### Negative
- Initial setup complexity
- Learning curve for team members
- Some tools require specific Node.js versions

## Migration Path

If we need to change tools in the future:
1. Keep all code as-is (no lock-in)
2. Use pnpm's `pnpm dedupe` to manage nested dependencies
3. Gradually migrate packages one at a time
