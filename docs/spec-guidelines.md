# Specification Guidelines

## Required Sections

All M0 specifications must include:

1. ## Overview - High-level description of the feature
2. ## Goal - Primary objective
3. ## Scope - In-scope items
4. ## Non-scope - Out-of-scope items
5. ## Data model changes - Database schema changes
6. ## API endpoints - New/modified API endpoints
7. ## UI - UI changes and user experience
8. ## Acceptance tests - Criteria for acceptance
9. ## Demo end state - Expected final state
10. ## Devlog prompt - Instructions for implementation
11. ## Locked decisions covered - Decisions already made

## Format Requirements

- Use Markdown headers (## for top-level sections)
- Use bullet points for lists
- Include code blocks for technical details
- Keep language clear and concise

## Review Checklist

Before submitting a specification:

- [ ] All required sections are present
- [ ] Headings follow the naming convention
- [ ] Code examples are valid
- [ ] Acceptance criteria are testable
- [ ] Dependencies are documented
