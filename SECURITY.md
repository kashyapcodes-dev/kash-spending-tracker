# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please report it responsibly.

### How to Report

1. **Do NOT** create a public GitHub issue for security vulnerabilities
2. Send an email to: security@kash-spending-tracker.com
3. Include the following information:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if applicable)

### Response Time

We aim to respond to all security reports within 48 hours.

### What We Do With Your Report

- We will acknowledge receipt within 48 hours
- We will keep you informed of our progress
- We will credit you publicly when we fix the issue (unless you request otherwise)
- We may ask for additional information or clarification

### What We Don't Accept

- Vulnerabilities that are already known and disclosed publicly
- Issues that are not security-related
- Requests for payment or other compensation

## Security Best Practices

### For Contributors

- Never commit sensitive data (API keys, passwords, tokens)
- Review code for potential security issues
- Use dependency updates to stay current with security patches
- Follow secure coding practices

### For Users

- Keep dependencies updated (`pnpm update`)
- Review environment variables before deployment
- Use strong authentication mechanisms
- Regularly audit access controls

## Security Updates

Security-related updates will be released promptly. Critical fixes may be backported to previous versions if necessary.
